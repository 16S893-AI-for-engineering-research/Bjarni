Explanation

Plan: recreate and extend TASOPT's airfoil drag tables with XFOIL

Scope: Uncommitted backlog plan on top of the current worktree commit

The plan has two milestones and eleven tasks in backlog. Milestone A rebuilds C.air with XFOIL and checks it against the original. Milestone B extends the table to thinner, faster TBW sections. The main risk is physical: XFOIL cannot model shocks, so the transonic drag rise needs a calibrated add-on.

How TASOPT uses the airfoil table

The TOML key [Wing] airfoil names a file in src/airfoil_data/. airtable reads that file once and builds splines. airfun then interpolates section drag and moment for the wing drag code.

  • File format: a header nM ncl ntc nfun, then the M, cl and t/c lists, then one Re value. After that come rows of cdf cdp cm, ordered t/c outermost and M innermost.
  • Callers found with codemap: read_aircraft_model calls airtable. wing_profiledrag_direct and aeroperf_sweep call airfun.
  • Outside the cl and t/c bounds, airfun adds a quadratic penalty to cdp. Mach outside the grid is extrapolated with no penalty.

Why TBW needs a bigger table

All three shipped tables stop at t/c 0.09 and M 0.81, at Re 2×1072\times10^72×107. TBW wings want t/c around 0.07 or less and M⊥M_\perpM⊥​ up to about 0.85.

  • At t/c 0.07 the penalty is 100 drag counts. That is several times a typical section cdp, so it is a numerical artefact, not physics.
  • C.air and Cl.air share the same grid. E.air adds cl 0.75 and uses a different Mach list.

The plan in backlog

Milestone A (recreate) comes before milestone B (extend). In B, the accuracy of the extrapolation can only be checked against literature, so A has to validate the pipeline first.

  • Tasks 1 to 4 build the tools: a headless XFOIL build from the Mac fork, a .air reader and writer, the section geometry, and a batch driver.
  • Task 5 is where parallel subagents run, one folder per approach.
  • Tasks 6 and 7 assemble C_xfoil.air and compare aircraft sizing results against C.air.
  • Tasks 8 to 10 define the TBW envelope, run thin sections and merge into C_tbw.air. Task 11 (optional) adds a strut section table.
  • Shipped tables are never overwritten. New files are selected via the TOML key.

## Key risks (read before dispatching)
1. **XFOIL is not a transonic solver.** It uses a Kármán–Tsien compressibility correction and stops being
   valid once the flow is locally supersonic. The C-series data came from Drela's 2-D viscous/inviscid
   CFD (MSES), with the drag rise in M 0.70–0.81 driven by shock/wave drag. XFOIL alone will reproduce the
   low-Mach part and will **not** reproduce the drag rise. Plan A therefore compares several
   "XFOIL + transonic treatment" approaches (see decision-1).
2. **The C-/E-series geometry is not in the repo.** Without coordinates, "recreate" means "find or fit an
   airfoil family that reproduces the table". Finding the original coordinates is task 3.
3. **Re = 2e7, fully turbulent** (TASOPT's Re exponent assumes it). XFOIL runs need forced transition
   near the leading edge (`XTR` ≈ 0.02–0.05) except for `Cl.air` (lower-surface laminar to ~0.6 c).
4. **cdf / cdp split.** XFOIL gives `CD` and `CDp`; take `cdf = CD − CDp`, `cdp = CDp` (+ wave drag). Check

5. **Spline robustness.** `airtable` builds cubic splines across every axis, so noisy or non-converged points
   cause wiggles. Every generated table needs gap-filling and smoothness checks.

## Context
The shipped C/Cl/E tables were produced by Drela with 2-D viscous/inviscid transonic CFD (MSES) at
Re = 2e7 for a designed transonic family. XFOIL (the requested tool) is subsonic: Kármán–Tsien correction,
no shocks, so it cannot reproduce the drag rise above roughly M 0.65–0.72 by itself. The original section
coordinates are not in the repo.

## Decision (proposed, to be settled after the A-lane comparison)
- Use XFOIL (nolankucd/Xfoil-for-Mac build, run headless, batch-driven) for cdf, cdp, cm below the
  critical Mach number.
- Add a transonic treatment chosen from lanes A2/A3 by how well it reproduces C.air above M 0.6
  (calibrated Korn/Lock wave drag is the default candidate). Store it in `cdp` (TASOPT ignores `cdw`).
- Keep a single regular (M, cl, t/c) grid, Re = 2e7, fully turbulent, same file format.
- Use MSES or another transonic solver for spot checks only if it is available (lane A4).

## Consequences
- The XFOIL-only region is "recreated"; the transonic region is a calibrated model, so it is reported
  separately in all validation.
- The same pipeline and calibration extrapolate to t/c < 0.09 and M > 0.81 in B. Their accuracy there
  cannot be validated against C.air, so it needs literature checks.
